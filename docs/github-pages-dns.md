# GitHub Pages Custom Domain and HTTPS Setup

Guide for configuring custom domains on GitHub Pages for the MRover organization.

## Overview

We currently uses two GitHub Pages sites:

| Repo | Custom Domain | Type |
|------|--------------|------|
| `umrover/mrover-website` | `mrover.org` | Apex domain |
| `umrover/mrover-docs` | `docs.mrover.org` | Subdomain |

Both deploy via GitHub Actions using `actions/upload-pages-artifact` and
`actions/deploy-pages`.

## Setup Checklist for a New Subdomain

Example: adding `new.mrover.org` on the `umrover/new-repo` repository.

### 1. DNS CNAME

At the registrar (Namecheap, ask the ERO for details to access), add a CNAME pointing to the org's GitHub
Pages domain:

```
new.mrover.org.  CNAME  umrover.github.io.
```

For an apex domain, use A records instead (you cannot CNAME an apex):

```
mrover.org.  A  185.199.108.153
mrover.org.  A  185.199.109.153
mrover.org.  A  185.199.110.153
mrover.org.  A  185.199.111.153
```

### 2. DNS CAA (Certificate Authority Authorization)

GitHub Pages uses Let's Encrypt for SSL certificates. Add a CAA record for
every domain and subdomain that uses GitHub Pages:

```
new.mrover.org.  CAA  0 issue "letsencrypt.org"
```

This must be added per-subdomain. Some DNS providers return NXDOMAIN for
subdomains missing their own CAA record instead of falling through to the
parent domain, which silently blocks GitHub's certificate provisioning.

On Namecheap, the `host` field should be the subdomain string (eg. `docs`), choose `issue` from the dropdown, and input the value as `letsencrypt.org`. 

### 3. GitHub Organization Domain Verification

GitHub requires domain verification at the org level before it will
provision SSL certificates.

1. Go to **github.com/organizations/umrover/settings/pages**
2. Click **Add a domain**
3. Enter the domain (e.g. `new.mrover.org`)
4. GitHub gives you a TXT record value to add at the registrar:
   ```
   _github-pages-challenge-umrover.new.mrover.org.  TXT  "<value from GitHub>"
   ```
5. Add the TXT record, wait for propagation, then click **Verify**

Each domain and subdomain must be verified separately.

### 4. Set Custom Domain in Repo Settings

Go to the repo's **Settings > Pages** and enter the custom domain
(e.g. `new.mrover.org`).

For repos deployed via GitHub Actions, you do **not** need a `CNAME` file in the repo. That was for deploy from branch. 

### 5. Wait for SSL Certificate

GitHub automatically provisions a Let's Encrypt certificate once DNS, CAA,
and org verification are all in place. This typically takes 15-30 minutes.

### 6. Enable HTTPS

Once the certificate is issued, the **Enforce HTTPS** checkbox in the repo's
Pages settings will become available. Check it.

If the checkbox is grayed out, the certificate has not been issued yet.
Go back and verify that steps 1-3 are all correct.
